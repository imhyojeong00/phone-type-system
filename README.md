# Phone-Type System — 휴대폰 타이핑 시스템

## 이 사이트가 존재하는 이유

휴대폰은 "들고 다닐 수 있는" 사물이 되기 위해 계속 얇아지고 가벼워졌습니다. 그래서 휴대폰의
계보는 사진 한 장이 아니라 **부피**로 읽어야 합니다. 모든 휴대폰을 **같은 자(실제 mm)**로 재어
3D로 세우고, 글자를 치면 그 글자의 휴대폰이 두께 0의 판에서 제 두께만큼 부풀어 오릅니다.

## 실행

`index.html`을 더블클릭해서 바로 열면 됩니다(서버 필요 없음, 인터넷 필요 없음).
한글 입력 상태여도 자판 위치로 알파벳을 읽습니다.

## 한 글자 = 두 휴대폰의 접목체

글자를 치면 그 글자의 휴대폰과 **짝 휴대폰**(`data.js`의 `with`, 기본은 계보의 바로 다음
휴대폰 — A는 DynaTAC × MicroTAC, …, X는 처음 A와 이어짐)이 서로의 몸을 꿰뚫고 섞여 하나의 새
개체로 태어납니다. 맞닿은 자리는 표면이 부풀어 일그러지고, 노이즈 모양 구멍이 뚫려 두 몸이
서로의 틈으로 비치며, 때 묻은 듯 거뭇해집니다. 짝 휴대폰은 조금 늦게 차올라 글자의 휴대폰에서
돋아나듯 보입니다. 같은 글자는 늘 같은 모양으로 접목됩니다.

개체끼리도 나란히 서지 않고, 새 개체가 앞 개체의 몸 속으로 파고들며 이어붙습니다. 휴대폰은 기울지 않고 모두 똑바로 섭니다 — 위치(가로 · 높이 · 깊이)만 어긋나 서로의 몸에 박힙니다.
원본과 X-RAY는 같은 자리 · 같은 모양이고 재질만 바뀝니다.

## 조작

| 입력 | 동작 |
|---|---|
| A–Z | 휴대폰 만들기 |
| 드래그 | 시점 돌리기(사물은 가만히, 보는 눈이 둘레를 돈다). 처음엔 정면 — 평면 이미지처럼 보이고, 돌리면 부피가 드러난다. 더블클릭하면 정면으로 |

## 같은 자로 재기

- 모든 휴대폰은 실제 크기로 맞춰집니다(100mm = 장면 1단위). 3D 모델의 폭(열어도 변하지
  않는 치수)을 실제 mm에 맞췄고(`data.js`의 `fit`), 옛 휴대폰일수록 크게 보입니다.
- 받은 3D 모델은 대부분 실제보다 훨씬 두껍게 만들어져 있습니다(예: iPhone 13 Pro 모델은 실제의
  약 7배 두께). 얇아지는 계보가 보이도록 바(bar)형 휴대폰 14대는 두께를 실제 두께로 눌러
  맞췄습니다(`thick: true`). 폴더·슬라이드·도크처럼 열린 상태의 모델은 그대로 둡니다.
- 가운데 휴대폰의 크기에 맞춰 카메라 거리가 자동으로 바뀝니다.

## 라벨

- 이름 · 연도 · (목록과 3D가 다르면 메모)
- 폭 · 높이 · 두께 mm, 무게 g, 그리고 **두께 막대**(끝 = DynaTAC 89mm)와 **무게 막대**(끝 =
  DynaTAC 794g) — 같은 막대로 얇아지고 가벼워지는 정도를 비교
- Y · Z는 가장 두꺼운 것과 가장 얇은 것을 같은 막대로 나란히
- 크기와 무게는 공개된 제원을 옮긴 **대략값**입니다. `data.js`에서 확인 후 고쳐 주세요.

## 휴대폰의 물성을 옮긴 방식

| 물성 | 화면 | 소리 |
|---|---|---|
| 부피가 생김 | 두께 0의 납작한 판으로 조금 떠 있다가, 제 두께만큼 느리게 차오름(무거울수록 더 느리게) | 둔한 압력 → 낮게 눌린 바람 |
| 무게 | 차오르는 동안 무게에 끌려 점점 빨라지며 내려와 닿고, 되튀지 않고 눌린 채 천천히 풀림. 화면도 한 번 가라앉음 | 무거울수록 낮고 길게 깔리는 쿵 |
| 전원 | — | 짧은 진동(햅틱) |
| 속(부피) · 접목 | X-RAY: 몸체가 거친 입자의 덩어리가 되고, 겹친 몸들은 경계 없이 검게 뭉침. 맞닿은 자리는 입자가 짙어지고 표면이 부풀어 일그러짐(유합조직). 새 개체는 앞 개체와 맞닿은 자리에서부터 번져 자라 나옴 | 스위치 소리 |

## 3D 파일

- 받은 .glb(Draco 압축)를 브라우저가 서버 없이 읽을 수 있는 형태(meshopt 압축, 텍스처
  1024px)로 바꾸고, 글자(base64)로 담아 `assets/models/<목록 번호>.js`로 넣었습니다.
  글자를 칠 때 필요한 것만 불러오고, 열어 둔 동안 계보 순서대로 미리 불러 둡니다.
- 21(iPhone Xs)·23(iPhone 13 Pro) 모델은 뒷면이 정면을 보고 있어 180° 돌렸습니다(`rotY`).

## 파일

| 파일 | 내용 |
|---|---|
| `data.js` | 알파벳 배정, 이름·연도·실제 크기·무게·맞춤 기준 |
| `script.js` | 3D 장면, 등장(부피·무게), 겹친 것(Y·Z), 타이핑 줄, X-RAY, 시점, 소리 |
| `style.css` | 화면 요소 |
| `vendor/` | three.js r147, GLTFLoader, meshopt 디코더, RoomEnvironment |
| `assets/models/` | 휴대폰 3D(.js) 23개 + Nokia 8110 사진(.js) |

## 조절할 수 있는 값 (`script.js` 맨 위)

| 값 | 뜻 |
|---|---|
| `FOV` | 화각. 작을수록 정면이 납작한 평면처럼 보인다(기본 9°) |
| `INFLATE_MS` · `SETTLE_MS` | 차오르는 시간 · 닿은 뒤 풀리는 시간 — 늘릴수록 무겁다 |
| `PARTNER_DELAY` | 짝 휴대폰이 얼마나 늦게 차오르는지(0 = 같이) |

한 글자 안 두 휴대폰이 꽂히는 모양은 `placePhone`의 `parts[1].node.position`에서,
개체끼리 파고드는 모양은 같은 함수의 `cur`에서, 접목 부위의 구멍 · 얼룩은 `MESSY_FRAG_*`,
입자의 밀도는 `makeXrayMat`의 셰이더에서 바꿀 수 있습니다.
